# m3 — Control flow

## L1 — Booleans & comparisons

**Concept.** **Control flow** is how a program decides what to do and how often. It starts with questions that answer `True` or `False`. **Comparison operators** ask those questions: `==` (equal?), `!=` (not equal?), `<`, `>`, `<=`, `>=`. So `3 < 5` is `True`, `3 == 5` is `False`. Note the double `==` for "equal?" — a single `=` means assignment (store), never comparison. You can combine questions with `and` (both true), `or` (either true), and `not` (flip it).

**ELI5.** A boolean is a yes/no answer. Comparisons are the yes/no questions: "is this bigger than that?" `and`/`or`/`not` let you chain questions: "is it raining *and* cold?"

**Deep dive (optional).** Beware `==` vs `is`. `==` asks "are these two values equal?"; `is` asks "are these the exact same object in memory?" They often agree for small numbers by luck, but the rule is: use `==` to compare values, and reserve `is` for `x is None`. Relying on `is` to compare numbers or strings is a classic bug that works until it suddenly doesn't.

**Build-task tie-in.** The todo app constantly asks boolean questions: "is this task done?" (`task_done == True`, or just `if task_done:`), "did the user type `quit`?" (`choice == "quit"`).

**Check.** Learner can write a comparison that evaluates to `True`, and explain why `==` and `=` are different.

## L2 — `if` / `elif` / `else`

**Concept.** `if` runs a block of code only when a condition is `True`. `elif` ("else if") offers another condition to try when the ones above were `False`. `else` is the catch-all when nothing above matched. Python groups the block by **indentation** (the spaces at the start of the line) — not braces, not keywords. Everything indented under the `if` belongs to it.

```python
if priority > 2:
    print("urgent")
elif priority == 2:
    print("soon")
else:
    print("whenever")
```

**ELI5.** It's a fork in the road with signs. "If urgent, go left. Else if soon, go straight. Otherwise, go right." Python checks the signs top to bottom and takes the *first* one that fits, then skips the rest.

**Deep dive (optional).** Only the first matching branch runs, then the whole `if/elif/else` is done — it does not keep checking. Indentation is part of the language's meaning, not decoration: mixing tabs and spaces, or indenting inconsistently, is itself an error (`IndentationError`). Pick four spaces and stay consistent.

**Build-task tie-in.** This is the todo app's menu: `if choice == "add": ... elif choice == "list": ... else: print("unknown command")`. The whole app is one big `if/elif/else` reacting to what the user typed.

**Check.** Learner can write an `if/elif/else` with three branches and explain that only the first matching branch runs.

## L3 — `while` loops

**Concept.** A **loop** repeats code. A `while` loop repeats *as long as* its condition stays `True`, re-checking before each pass:

```python
running = True
while running:
    choice = input("command> ")
    if choice == "quit":
        running = False
```

Use `while` when you don't know how many times you'll loop — you loop *until* something changes.

**ELI5.** "Keep stirring *while* it's lumpy." You don't know how many stirs; you stop when the condition (lumpy) becomes false.

**Deep dive (optional).** If the condition never becomes `False`, you get an **infinite loop** — the program runs forever. Every `while` needs something inside it that can eventually flip the condition (here, setting `running = False`). `break` exits a loop immediately; `continue` jumps to the next pass. Ctrl-C stops a runaway program from the terminal.

**Build-task tie-in.** The todo app's main loop is a `while`: keep showing the menu and handling commands *until* the user types `quit`. That's exactly the "loop until something changes" shape.

**Check.** Learner can write a `while` loop that ends, and say what causes an infinite loop.

## L4 — `for` loops & `range`

**Concept.** A `for` loop does something once *for each item* in a collection:

```python
for task in tasks:
    print(task)
```

Here `task` takes the value of each item in `tasks` in turn. When you just need to repeat a fixed number of times, `range(n)` gives you the numbers `0, 1, ... , n-1` to loop over: `for i in range(3):` runs three times with `i` being `0`, then `1`, then `2`.

**ELI5.** `for` is "do this to every item in the box, one at a time." `while` is "keep going until I say stop." Use `for` when you have a known pile to go through; use `while` when you're waiting for a condition.

**Deep dive (optional).** The big gotcha: `range(3)` is `0, 1, 2` — it *starts at 0* and *stops before* the number you give it, so it yields exactly 3 values but never reaches 3. `range(1, 4)` gives `1, 2, 3`. This off-by-one feels odd at first but makes `range(len(tasks))` line up perfectly with list positions, which also start at 0 (m5).

**Build-task tie-in.** Listing tasks is a `for` loop: `for task in tasks: print(task)`. To number them for the user, loop with positions: `for i, task in enumerate(tasks): print(i + 1, task)` — `enumerate` hands you both the position and the item.

**Under the hood.** A `for` loop asks the collection for an **iterator** — a little helper that coughs up one item at a time and says "done" when empty. `range` doesn't build a giant list of numbers in memory; it generates each number as the loop asks for it, so `range(1_000_000)` costs almost nothing until you actually loop.

**Check (mastery bar for m3).** Learner can write an `if/elif/else` and a `for` loop over `range`, state that `range(n)` goes `0` to `n-1`, and explain when to choose `while` (loop until a condition changes) versus `for` (loop over known items).
