# m6 — Strings & text

## L1 — Indexing & slicing

**Concept.** A string is a sequence of characters, so you can reach into it by position, exactly like a list. **Indexing** grabs one character: `s = "hello"`, `s[0]` is `"h"`, and negative indexes count from the end, so `s[-1]` is `"o"`. **Slicing** grabs a range: `s[1:4]` is `"ell"` — start at index 1, stop *before* index 4. Leave an end off to go to the edge: `s[:2]` is `"he"`, `s[2:]` is `"llo"`.

**ELI5.** Think of the string as beads on a thread, numbered from 0. Indexing picks one bead; slicing snips out a run of beads. The "stop before" rule means `s[1:4]` gives you beads 1, 2, 3 — the same off-by-one you met with `range`.

**Deep dive (optional).** Slicing takes an optional step: `s[::2]` takes every second character, and `s[::-1]` walks backwards — the idiomatic way to reverse a string. A slice always makes a *new* string; the original is untouched (which it must be — see L3). An index past the end (`s[99]`) errors, but a slice past the end (`s[1:99]`) just stops at the end, no error.

**Build-task tie-in.** The todo app parses typed commands like `"add buy milk"`. Slicing off the command word — `rest = command[4:]` to drop `"add "` — is one simple way to pull out the task text (we'll meet a cleaner way with `.split()` in L3).

**Check.** Learner can index a character, take a slice, and explain that a slice stops *before* its end index.

## L2 — f-strings

**Concept.** An **f-string** builds text out of values. Put `f` before the opening quote, then drop any expression inside `{curly braces}`:

```python
name = "Sam"
count = 3
print(f"{name} has {count} tasks")   # Sam has 3 tasks
```

Anything inside the braces is evaluated and its value dropped into the text. It's the clearest way to mix fixed words with live values.

**ELI5.** An f-string is a fill-in-the-blanks sentence. You write the sentence with blanks in braces, and Python fills each blank with the current value of what's inside.

**Deep dive (optional).** You can format inside the braces after a colon: `f"{price:.2f}"` shows two decimals (`3.10`), `f"{n:>5}"` right-aligns in 5 spaces — handy for lining up columns. `f"{count=}"` prints `count=3`, name and value together, which is a quick debugging trick. The braces hold a real expression, so `f"{count + 1}"` works too.

**Build-task tie-in.** Every line the todo app shows the user is an f-string: `f"{i + 1}. [{mark}] {task['text']}"` prints a numbered task with a `[x]` or `[ ]` done-marker. f-strings are how the app turns its data back into readable text.

**Check.** Learner can write an f-string that inserts two variables into a sentence.

## L3 — Common string methods (and why they return new strings)

**Concept.** Strings come with built-in **methods** — functions you call on the string with a dot:
- `"  hi  ".strip()` → `"hi"` (trim surrounding whitespace)
- `"Hi".lower()` / `.upper()` → `"hi"` / `"HI"`
- `"add buy milk".split()` → `["add", "buy", "milk"]` (break on spaces into a list)
- `"a,b,c".split(",")` → `["a", "b", "c"]`
- `",".join(["a", "b"])` → `"a,b"` (the inverse of split)
- `"buy milk".replace("milk", "bread")` → `"buy bread"`
- `"buy milk".startswith("buy")` → `True`

Every one of these **returns a new string**; none changes the original.

**ELI5.** You can't edit the beads on the thread — strings are set in stone (immutable). So `.upper()` doesn't shout the existing string; it hands you a brand-new all-caps copy. If you want to keep it, catch it: `loud = s.upper()`.

**Deep dive (optional).** This is the number-one string bug: writing `name.strip()` on its own line and expecting `name` to change. It doesn't — strip made a cleaned copy and you threw it away. You must reassign: `name = name.strip()`. Strings are immutable precisely because that makes them safe to share freely and usable as dict keys (m5); the cost is that every "edit" is really a new value.

**Build-task tie-in.** Parsing a command cleanly: `parts = command.strip().lower().split()` trims stray spaces, lowercases so `"ADD"` works, and splits into words — then `parts[0]` is the command and `" ".join(parts[1:])` is the task text. This replaces the fragile slicing from L1.

**Under the hood.** Because a string never changes, Python can safely let several names point at the same string in memory and can reuse identical short strings. That immutability is also why building a big string by repeated `+=` in a loop is wasteful (each step makes a whole new string) — for heavy assembly you collect pieces in a list and `"".join(...)` them once at the end.

**Check (mastery bar for m6).** Learner can slice a string, build one with an f-string, use a method like `.split()` or `.strip()`, and explain that strings are immutable — so methods return a new string that you must capture.
