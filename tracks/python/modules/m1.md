# m1 — Setup & running your first code

> Lesson content for the `teach` skill. Teach one lesson at a time, at the learner's level, then check. Don't dump the whole file at them.

## L1 — Installing Python and checking it's really there

**Concept.** Python is a **language** (a set of rules for writing instructions) and also a **program** (called the *interpreter*) that reads those instructions and does them. To write Python you first install that interpreter. On most machines you then have a command called `python3` (sometimes just `python`). You check it's installed by asking it its version: `python3 --version` prints something like `Python 3.12.4`. If you see a version number starting with 3, you're ready.

**ELI5.** Python is both the recipe language *and* the cook who can read it. Installing Python hires the cook; checking the version is just asking "are you here, and which one are you?"

**Build-task tie-in.** Everything we build in this track — starting with a command-line todo app — runs through this interpreter. Getting it installed and confirmed is step zero of the whole project.

**Under the hood.** When you type `python3`, your operating system looks through a list of folders (your `PATH`) for a program by that name and runs it. "Command not found" almost always means the install finished but that folder isn't on the PATH yet — an install problem, not a you problem.

**Check.** Learner can run `python3 --version` and read back a 3.x version number, and say that Python is both a language and the program that runs it.

## L2 — The interpreter and the REPL

**Concept.** If you run `python3` with no file, you get a **REPL** — Read, Evaluate, Print, Loop. You type one line, press Enter, and it instantly runs that line and shows the result. Type `2 + 2` and it prints `4`. Type `print("hello")` and it prints `hello`. The `>>>` prompt means "your turn." You leave with `exit()` or Ctrl-D. The REPL is a sandbox for trying one idea at a time.

**ELI5.** The REPL is like texting the cook a single instruction and getting an answer back right away, before you commit to writing down a whole recipe.

**Deep dive (optional).** "Evaluate" means Python works out the *value* of what you typed. `2 + 2` has the value `4`, so it prints `4`. `print(...)` has no real value (it shows `None` if you inspect it) but it has a *side effect*: putting text on screen. Noticing the difference between "what is this worth" and "what does this do" is the start of reading code well.

**Build-task tie-in.** Before we add a feature to the todo app, we'll often test the idea in the REPL first — e.g. try `"buy milk".upper()` to see what a string method does — then put the working line into our file.

**Check.** Learner can open the REPL, evaluate `2 + 2`, run a `print(...)`, and exit.

## L3 — Running a `.py` file

**Concept.** The REPL forgets everything when you close it. To keep a program, you save your instructions in a **file** ending in `.py` (a plain text file, nothing special) and run the whole file at once with `python3 myfile.py`. The interpreter reads the file top to bottom and does each line in order. This is how every real program is stored and shared.

**ELI5.** The REPL is talking to the cook live; a `.py` file is writing the recipe down so the cook can make the whole dish from start to finish, the same way every time.

**Deep dive (optional).** The lines run strictly top to bottom — order matters. If line 5 uses something you only define on line 9, it fails, because line 9 hasn't happened yet when line 5 runs. Unlike the REPL, a script only shows output you explicitly `print`; evaluating `2 + 2` on its own line in a file shows nothing, because a file doesn't auto-print values the way the REPL does.

**Build-task tie-in.** Our todo app lives in a file, e.g. `todo.py`. We create it now with a single line — `print("Todo app starting...")` — and run it with `python3 todo.py`. That's our first real, saved program; every later module adds to this file.

**Under the hood.** `python3 todo.py` starts the interpreter, which reads your text file, translates it into low-level instructions called **bytecode**, and executes them. You never see the bytecode; you just see your `print` output. Same interpreter as the REPL — only the input source differs (a file instead of your live typing).

**Check (mastery bar for m1).** Learner can run a one-line program both in the REPL and from a saved `.py` file, and explain the difference: the REPL runs and prints one line at a time and forgets; a file is saved, runs top to bottom, and only prints what you tell it to.
