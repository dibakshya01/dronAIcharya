# m2 — Values, variables & types

## L1 — Values and their types

**Concept.** A **value** is a single piece of data: the number `7`, the text `"hello"`, the answer `True`. Every value has a **type** that says what kind of thing it is and what you can do with it. The four you meet first:
- `int` — whole numbers: `7`, `-3`, `0`
- `float` — numbers with a decimal point: `3.14`, `-0.5`, `2.0`
- `str` — text ("string" of characters), written in quotes: `"hello"`, `'a'`
- `bool` — a truth value, exactly one of `True` or `False`

You can ask any value its type with `type(7)`, which answers `<class 'int'>`.

**ELI5.** A value is a thing; its type is what *kind* of thing it is. A number and a word are both "things," but you can do arithmetic on one and spell-check the other. The type is how Python knows which operations make sense.

**Deep dive (optional).** Type decides how an operator behaves. `+` on two ints adds (`2 + 2` → `4`); `+` on two strings joins them (`"ab" + "cd"` → `"abcd"`). The same symbol, different jobs, chosen by type. That's why mixing types in `"3" + 3` is an error: Python won't guess whether you meant `6` or `"33"`.

**Build-task tie-in.** Our todo app holds exactly these types: a task's text (`str`), maybe a priority number (`int`), and whether it's done (`bool`). Naming the type of each piece now saves confusion later.

**Check.** Learner can name the four basic types and give an example value of each.

## L2 — Variables & assignment

**Concept.** A **variable** is a name you attach to a value so you can refer to it later. You create one with `=`, called **assignment**: `task = "buy milk"`. Now the name `task` points at the string `"buy milk"`, and anywhere you write `task` Python uses that value. Read `=` as "gets" or "is now," never as "equals" — it's an action (store this), not a question.

**ELI5.** A variable is a luggage tag. `task = "buy milk"` ties the tag labelled `task` onto the suitcase `"buy milk"`. Later you just say "bring me `task`" and you get that suitcase.

**Deep dive (optional).** Assignment binds a *name* to a *value*; it doesn't copy the value. You can re-point the tag any time — `task = "buy bread"` moves the `task` tag to a new suitcase and the old one is forgotten (if nothing else points to it). A name and a value are separate things: one value can wear several tags, which matters a lot once we reach lists (m5).

**Build-task tie-in.** In the todo app we'll store the user's typed task in a variable, e.g. `new_task = input("Task: ")`, then use `new_task` wherever we need it. `input()` always hands back a `str`, which is about to matter.

**Check.** Learner can assign a variable and explain that `=` stores a value under a name, it doesn't test equality.

## L3 — Dynamic typing & converting between types

**Concept.** Python is **dynamically typed**: you never declare what type a variable holds, and the same name can point at an `int` now and a `str` later. The *value* carries the type, not the variable. But Python is also strict about mixing: `"3" + 3` raises an error, because one is text and one is a number. To combine them you **convert** on purpose: `int("3")` turns the string `"3"` into the number `3`; `str(3)` turns the number into `"3"`; `float("2.5")` gives `2.5`.

**ELI5.** You don't tell Python "this tag is only ever for numbers." The suitcase itself knows what it is. And Python won't secretly repack a word into a number for you — if you want that, you say so with `int(...)`.

**Deep dive (optional).** "Dynamically typed" (checked as it runs) is different from "weakly typed." Python is *strongly* typed: it refuses nonsense like `"3" + 3` rather than silently guessing, which is why a conversion is explicit. Note `int("3.5")` fails — `"3.5"` isn't a whole number as text — but `int(3.5)` gives `3` by chopping off the decimal (it truncates toward zero, it does not round).

**Build-task tie-in.** This is the single most common beginner bug in the todo app: `input()` returns a `str`, so if you ask for a priority and do math on it, you must `int(...)` it first. `priority = int(input("Priority: "))` turns the typed text into a real number.

**Under the hood.** A conversion like `int("3")` doesn't change the original string; it *builds a new* int value. The string `"3"` still exists, untouched. Most "convert" operations in Python make a new value rather than altering the old one — a theme that returns with strings (m6).

**Check (mastery bar for m2).** Learner can name the four types, assign a variable, explain dynamic typing in one sentence, and say why `"3" + 3` errors and how to fix it (convert one side with `int(...)` or `str(...)`).
