# m2 — Prompting & the context window

## L1 — The context window: the model only sees what's in front of it

**Concept.** The **context window** is everything the model can "see" at once: your current messages, files you've shown it, tool results, and its own recent replies. It has a size limit. Anything outside that window — a file you never opened, a fact from last week's chat that scrolled away — effectively doesn't exist for the model right now.

**ELI5.** Think of the model looking through a window at a desk. It can only use the papers currently on the desk. If a paper isn't on the desk, it can't read it — even if it's in the next room.

**Deep dive (optional).** The window is measured in tokens. Everything (system instructions, history, files, the answer being written) shares that budget. When it fills, older content gets summarized or dropped ("compaction"), which is why very long sessions start to "forget." (This is exactly why dronAIcharya re-anchors its teaching contract with a hook on session start.)

**Build-task tie-in.** When we build, we'll *put the relevant file on the desk* (open/paste it) instead of hoping the model remembers it.

**Check.** Learner can say the model only uses what's in its context window right now.

## L2 — Prompting that works

**Concept.** Good prompting = being specific, giving examples, and handing the model the material. Three reliable moves: (1) say exactly what you want and in what form; (2) show an example of a good answer; (3) paste the actual code/data/spec it needs rather than describing it from memory.

**ELI5.** It's like asking a very capable intern. "Make it nice" gets you a shrug. "Here's the file, make the button blue and bigger, like this screenshot" gets you exactly what you wanted.

**Deep dive (optional).** Patterns: role/goal framing, few-shot examples, step-by-step ("think it through"), and constraints ("only change X"). For code, giving the file + the error + the goal beats any clever wording.

**Build-task tie-in.** We'll practice turning a vague wish ("make login work") into a precise, context-rich request.

**Check.** Learner can improve a weak prompt by adding specificity and the relevant material.

---

## L3 — Why long chats drift, and what context costs

**Concept.** Two practical truths: long conversations **drift** (early details fall out of the window and the model loses the thread), and context isn't free — more text in the window means more cost and slower, sometimes fuzzier answers. So we keep context *relevant*, not *maximal*.

**ELI5.** A giant messy desk is as useless as an empty one. You want the *right* few papers on it.

**Deep dive (optional).** Cost scales with tokens processed; stuffing everything in every turn is the classic beginner tax. Techniques: start a fresh focused chat for a new sub-task, paste only the relevant file, summarize long threads. (dronAIcharya itself injects only a short status crumb each turn, not the whole contract, for exactly this reason.)

**Build-task tie-in.** If a session gets long and the model seems lost, we'll re-ground it with the current file and goal instead of scrolling up.

**Check (mastery bar for m2).** Learner can explain why giving the model the relevant file beats asking it to remember, and why bigger context isn't always better.
