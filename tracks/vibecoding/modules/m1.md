# m1 — What an LLM actually is

> Lesson content for the `teach` skill. Teach one lesson at a time, at the learner's level, then check. Don't dump the whole file at them.

## L1 — A large language model is a next-token predictor

**Concept.** An LLM (large language model) is a program that, given some text, predicts the most likely *next* chunk of text — one small piece (a "token") at a time — based on patterns it saw in a huge amount of text during training. It does this over and over to produce a whole answer. That's the whole trick, and it's a surprisingly powerful one.

**ELI5.** It's like the world's most well-read autocomplete. You know how your phone guesses the next word when you text? An LLM is that idea, scaled up enormously, so it can continue not just a word but an essay, a plan, or working code.

**Deep dive (optional).** Text is split into tokens (roughly word-pieces). The model turns tokens into numbers, runs them through a very large network that has learned statistical patterns, and outputs a probability for every possible next token. One is chosen, appended, and the process repeats. "Temperature" controls how adventurous the choice is. It is not retrieving stored sentences; it's computing likely continuations.

**Build-task tie-in.** When you ask dronAIcharya to write code for your app, it's *predicting the code most likely to follow your request and the context* — which is why giving it good context matters (next module).

**Under the hood.** There's no database of answers inside the model and no live internet unless a *tool* fetched something. The "knowing" is patterns baked into numbers.

**Check (mastery bar).** Learner can say, in their words, "it predicts the next token/word from patterns it learned," and that it isn't looking things up.

## L2 — Training vs. using, and the knowledge cutoff

**Concept.** There are two phases. **Training** (done once, by the model's makers) is where it reads a massive amount of text and adjusts its internal numbers — expensive, slow, done ahead of time. **Using** it (what you do) is fast and changes nothing permanent. Because training happened at a point in time, the model has a **knowledge cutoff**: it doesn't natively know about things after that date unless given them via context or a tool.

**ELI5.** Training is like going to school for years. Using it is like asking the graduate a question — they answer from what they learned, and they won't know yesterday's news unless you tell them.

**Deep dive (optional).** Fine-tuning and system prompts adjust behavior without full retraining. "Grounding" (giving it documents) and tool use (search) are how you get current or private facts in, since the base weights are frozen.

**Build-task tie-in.** If your app uses a brand-new library, the model may be out of date — so we'll fetch current docs (a tool) rather than trusting its memory.

**Check.** Learner can explain why an LLM might not know about a very recent thing, and name one way to fix that (give it the info / use a tool).

## L3 — Why it can be confidently wrong (hallucination)

**Concept.** Because the model predicts *plausible* text, it can produce something that sounds right but isn't — a made-up function, a wrong fact, a fake citation. This is called a **hallucination**. It's not lying; it's filling in the most likely-looking continuation even when it doesn't actually "know."

**ELI5.** Imagine a friend who hates saying "I don't know," so they confidently make up a believable answer. Useful often, dangerous sometimes — you learn when to double-check them.

**Deep dive (optional).** Hallucination rises when the prompt asks for specifics the model never reliably saw (exact numbers, obscure APIs, URLs). Grounding, tools, and asking it to show its reasoning or cite sources reduce but don't eliminate it.

**Build-task tie-in.** This is *why* module m6 (reading & trusting output) exists: we'll always check generated code runs and does what the spec says.

**Under the hood.** The model has no built-in "truth meter"; confidence in tone ≠ correctness.

**Check (mastery bar for m1).** Learner can explain "predicts the next token from patterns" AND name one reason it can be confidently wrong.
